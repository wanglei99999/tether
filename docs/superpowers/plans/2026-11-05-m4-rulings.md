# M4 混沌测试：执行中的决定

计划：`docs/superpowers/plans/2026-11-05-m4-chaos-testing.md`。每条写决定、理由和做错的代价。

## Task 1

- `planRound` 的参数用 `gapMs`（同一个会话两条消息的间隔），返回 `messageAt` 和 `durationMs`，取代计划里的 `durationMs` 参数和 `messageGaps`。"紧跟在发消息之后"的故障要知道每条消息的绝对时刻。代价：无，接口只有驱动程序在用。

## Task 2

- 模型可见的说明文本不在记录接口里（`toTranscriptEntry` 只带 `data`，文本在 pi 条目的 `model` 字段）。所以假模型把自己收到的说明写进 `TETHER_CHAOS_NOTES` 指向的文件，I4、I6 读它。查到的是模型真正收到的内容，比加接口更严格，也不用为测试改 API。代价：只能查到模型发过请求之后的说明，所以每个会话最后发两条消息（说明写在一轮中途时，模型下一轮才看到）。
- 一轮是 3 次工具调用加 1 条文本，令牌 `t0` 到 `t2`，文件只由 `t0`、`t2` 产生。被中断的调用也算一步，不重试原来那一步：令牌由工具结果数决定，这样实现最简单，也不影响检查。
- 分叉用单独的 `inspect:<分叉>:<序号>` 消息，模型只跑一条命令。这样分叉不会把继承来的 `chaos:` 消息接着往下做，文件列表也就只反映分叉点的工作区。

## Task 3

- I0 把 `unanswered` 也算违反。计划写的是"`unanswered` 带原因"，但 `waitSubmission` 的结果里没有原因字段（M1 暂缓项），而混沌测试不发中止、模型也不会失败，出现 `unanswered` 就是消息没被回答。代价：如果将来有正常的 `unanswered`，要放宽这条。
- I2 只查 `exec.log` 里同一个令牌的 `start` 不超过一条。从存档恢复后日志回滚，恢复前的重复会查不到（计划设计决定 3 的缺口）。

## Task 4

- `RoundReport` 记录每个故障是否碰到东西（`hit`）和总的被中断调用数，没有细到"每种故障打断了几次"。一次崩溃打断哪个调用要看时序，归因不可靠；`hit` 加总数足够判断有没有空转。代价：报告粒度粗一点。
- 破坏性对照在所有消息结束后向容器里的 `exec.log` 再写一条已有令牌的 `start`，没有真的把命令再跑一遍。要验证的是"日志从容器一路传到检查函数"，两者等价。
- `chaos.docker.test.ts` 进 `test:docker`，让 Docker 测试多跑约 2 分钟。它验证驱动程序本身，`npm run chaos` 才是混沌测试，后者不进 `npm test`。

## Task 5

- 计划只列了三个位置（存档钩子、工具执行中、创建沙箱），实测都不触发崩溃保护：工具先写执行意图，崩溃后得到"已中断"，算有进展；慢 `setup` 也是这样。所以加了 `model` 位置：模型请求 10 秒才回答，每 3 秒杀一次。计数只有在任务一直没提交新状态时才累积，这个位置才符合。
- 复现了问题 F1，结果在 `docs/acceptance/m4-chaos.md`。这里只记录，修复是下一轮。备选方案：`restartLimit` 设成 `Infinity`；停下时写说明并结束这一轮；启动时重试。

## Task 6

- 第一次全量（120 轮）有 12 轮报 I6，全部是检查函数误报：来源会话的容器被删后从模板重建，分叉继承的说明写的是"/workspace 里的文件都没了"，不逐条列出操作，检查函数只认逐条列出的。改为：来源在分叉点之前从模板重建过，重建前（最后一条 `lost` 之前）的文件允许缺失；从存档恢复的不放宽。代价：重建前、`lost` 写下之后才落盘的那一个工具结果，缺了也查不出来。
- 4 轮报 I7 是真的问题（F2）：快照复制完、`docker unpause` 因容器正在被删而失败，记录标成失败，复制出来的文件没有记录指向它，归档时删不掉，要到下次启动对账才清掉。
- 驱动程序的数据目录只按种子和轮号命名，三组同名，后一组会覆盖前一组保留的失败数据（第一次全量里 runc 组第 30、47 轮的数据因此丢了）。改为带上组名；失败的轮次另存 `history.json`，检查函数改了以后能直接重查。
- 修完重跑全量。第一次的汇总留在测试机 `~/chaos-out-run1`，报告里两次都写。
- 第二次全量 116/120 轮干净，4 轮都是 F2。报告写在 `docs/acceptance/m4-chaos.md`。失败轮次的数据目录留在测试机 `/data/tether-xfs/chaos/`，下一轮修 F2 时用来复现，修完删掉。
