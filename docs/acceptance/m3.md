## 验收中发现并修复的问题

- **容器在外部被删后，状态查询报错，永远标不成 `lost`。** 镜像模式的 Docker 卷和容器同名（`tether-<会话>`），容器删掉以后，不带类型的 `docker inspect` 找到的是卷，`{{.State.Status}}` 模板报错，`status()` 抛 `sandbox_failed` 而不是返回 `missing`；`fence()` 同样读到卷。自动测试没有覆盖"镜像模式下只删容器、卷还在"。修复：查容器的 `docker inspect` 一律加 `--type container`，补了用例。
- **归档后 `checkpoints/` 下留着空的会话目录。** 删掉一个会话的最后一张快照时没有删目录。修复：删快照后 `rmdir` 所在目录（不空就保留），补了用例。

两处修复后重新执行了整个验收，即上面的结果。

验收之后在 gVisor 下重跑全部 Docker 测试，又发现一处：

- **目录模式的快照可能混进上一张的旧文件。** "后台进程不停写入时存档"的用例在 runsc 下 15 次失败 2 次，恢复出的两个计数器来自不同的快照。先排除了暂停：runsc 下 `docker pause` 之后宿主上读计数器，3 秒内不再变化。原因是 `rsync --link-dest` 默认按整秒比较修改时间，同一秒内改过、长度不变的文件被当成没改，硬链接到上一张快照的旧内容；用例在几十毫秒里连存 3 张，正好撞上。和运行时无关，补了一个在 runc 下也稳定失败的用例（同一秒内两次写入同样长度的内容）。修复：`--modify-window=-1`，连纳秒一起比较；之后 runsc 下连跑 10 次全部通过。镜像模式是一次原子克隆，不受影响。

## 最终审查之后的重跑

最终审查发现：第四轮开始时沙箱已经丢失，这一轮的记录沿用第三轮的快照，却对齐到第四条消息；恢复时按它算"没有发生的操作"，从第四条消息算起，什么都不列，f3 其实已经没了。上面表格里"从最近的存档恢复"一行当时判为通过，是因为只看了文件，没核对说明。修复后（存档记录加 `basisCheckpointId`，查找和重建跳过沿用别的快照的记录）2026-10-29 重跑整个脚本，并加了一条断言：恢复用的必须是第三轮开始前那张（条目 31）。结果：

- 第四轮的记录 `entryId` 83、`basisCheckpointId` 指向条目 31 那张；恢复用的是条目 31 那张，说明从条目 31 往后列，包含写 f3 的那次调用。
- 分叉会话第一轮的记录、闲置删除后第五轮的记录同样带 `basisCheckpointId`；删除后的恢复用的是最终存档本身。
- 归档后快照文件、卷、工作区都是 0，`checkpoints/` 下没有空目录，测试机上只剩 loop0。

## 没有覆盖的

- 给模型的说明文字（`NOTES.restored`、`NOTES.forked`）只在单元测试里断言，会话记录的 API 只返回 `tether.*` 条目的 `data`，这里没有核对文字本身。
- 拉取不在本地的模板镜像：测试机访问 Docker Hub 不稳定，没有验证拉取成功的路径（拉取失败的路径有自动测试）。
- gVisor 下的端到端：只跑了全部 Docker 测试（`TETHER_SANDBOX_RUNTIME=runsc npm run test:docker`，全部通过），没有用 runsc 再走一遍这份脚本。
